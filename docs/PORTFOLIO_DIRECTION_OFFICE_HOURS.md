## Problem Statement

The current portfolio must stop reading like a general archive of past work. It should become a hiring document for a specific market signal:

> A mobile app developer with Flutter commercial app experience who is extending into FastAPI, ML, AI/RAG, and modern app-backend workflows.

The portfolio still needs to preserve the credibility of long Unity, education-content, and client-development experience, but that experience should support the current-positioning story instead of dominating the first impression.

## Hiring Goal

The portfolio's first job is to win interviews for roles around:

- Flutter mobile app developer
- mobile app developer with backend/API integration ability
- app developer who can attach AI/ML/RAG features to user-facing products
- client developer roles where Unity/content experience is still relevant

This is not a generic creative portfolio. It is a 16:9 horizontal hiring document that should help a reviewer decide:

> "This person has shipped mobile apps, can handle production-style client work, and is now current enough to work on Flutter + AI-enabled apps."

## Agreed Premises

1. This portfolio is not primarily a "senior Unity developer" portfolio. It is a **Flutter commercial app + AI/RAG expansion** portfolio.

2. Career history is a strength, but it should not be the first impression. The first impression should be current relevance: released apps, modern stack, backend/API, ML, and AI/RAG.

3. Slide 3 is the most important slide. It must not be a simple skills list. It must be a **Capability Matrix** that connects technology, project evidence, release evidence, and career evidence.

4. AI/RAG should appear more strongly in the portfolio than in the current resume. This is acceptable because resume revision will be handled later. The portfolio should avoid exaggeration and ground AI/RAG claims in `chatbot_rag`, FastAPI, ML/Transformer education, and RAG architecture.

5. The final deliverable is not a beautiful website for its own sake. It is a **PPT-convertible 16:9 hiring document** optimized for Flutter / mobile app / AI feature integration opportunities.

## Recommended Approach

### B. Hiring Narrative Redesign

Redesign all 12 slides around interview conversion.

The first five slides carry the hiring narrative. Later slides become evidence and appendix material. This avoids both extremes:

- Too shallow: only rearranging the current first five slides.
- Too risky: making AI/RAG the whole identity while the resume still leads with Flutter and Unity.
